## Gaps

- **Draft FR-28..FR-31 (Parts L and M) and FR-32..FR-34 (Parts Q and R)** each have tests. FR-34's tests mock the
  push service, so delivery to a real device is untested (REQUIREMENTS_STATUS: Partly met). FR-29's share email was
  checked through a stubbed transport, not a real mail provider.
- **Every FR now has at least one test.** FR-16 was the last without one (`handover.search.test.js`, Part H).
  NFR-17 is therefore met.
- **High-priority requirements that had no test, or only a partial one, at `23097ee`:** FR-01, FR-04, FR-05,
  FR-06, FR-11, FR-14. All have tests; FR-14's completion rate and shift window now exist and are tested.
- **Tested, but the requirement is only partly met by the code** (a test cannot fix this): FR-03 (cross-department
  directory and messaging, by design) and FR-17 (system notification rows and read receipts are not audited).
- Mutation checks: the first pass broke five behaviours on purpose and each was caught (see the first version of
  this file). In Parts H–K: making `withTransaction` commit on error failed 3 of 4 tests in
  `handover.submit-fault.test.js`; restoring it made them pass. Removing the old `Log out` fix made the touch-target
  script fail, which is how the 320 px header regression was found. In Parts L and M: letting any supervisor read any
  department's reports failed the `supB` row of the report access matrix; restoring the department check made it
  pass. The first versions of two tests passed for the wrong reason (a relink attempt with no task to link, an
  unlink on a report with no links) and were rewritten to use a report that has a linked task.
