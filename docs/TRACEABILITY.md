Client tests are in `client/src/test/` (Vitest + React Testing Library, jsdom). Test names are quoted exactly,
with their `describe` block in brackets where they have one.

## Gaps

- **High-priority requirements with no test, or only a partial one, before this change:** FR-01, FR-04, FR-05, FR-06, FR-11, FR-14.
  All six now have tests (21 new, all passing). No new test needed a code change.
- **Still without a test:** FR-16 (Medium). It is the only reason NFR-17 is not fully met.
- **Tested, but the requirement is only partly met by the code** (a test cannot fix this): FR-03 (cross-department
  directory and messaging), FR-14 (no completion rate, no shift window), FR-16 (no shift filter), FR-17 (system
  notifications and read receipts not audited).
- Mutation check of the new tests: five behaviours were broken on purpose (default task priority, the
  incoming-list filter, the dashboard `acknowledged` count, the one-department rule for non-admin roles,
  required incident severity). Each break made at least one new test fail. The first run missed the
  dashboard swap because two counts were equal. The test setup was changed so they differ, and the swap is
  now caught. All code was restored (`git diff server/src` is empty).
